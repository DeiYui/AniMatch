# AniMatch - 理由を説明できるアニメレコメンド
[English](./README.md) | **日本語**

![Status](https://img.shields.io/badge/Status-Demo-blue) ![Tech](https://img.shields.io/badge/Tech-Next.js_TypeScript-black) ![LLM](https://img.shields.io/badge/LLM-Gemini_(parsing_only)-purple) ![Data](https://img.shields.io/badge/Data-AniList_1000_titles-02a9ff)

## 📖 概要 (Overview)
今の状況をひとことで書くと、理由つきでアニメを3本おすすめします。画面は **日本語と英語** を切り替えられ（JA / EN）、どちらのモードでも日本語・英語のどちらで入力しても構いません。

> 「仕事で疲れた。寝る前に30分だけ笑えるやつ」

入力を省きたいときは、入力欄の下の **クイック選択** を使えます。
- 気分は大きめのボタンで選びます。
- 時間（15分〜一気見）と「一緒に」はコンパクトな切り替えボタンです。
- それ以外（映画 / シリーズ、完結済みのみ、最近の作品 / 昔の名作、有名作 / 隠れた名作、見たくないもの）は **「こだわり条件」** ボタンにまとめています。ボタンには選択中の数が表示され、PC ではポップオーバー、スマホではボトムシートで開きます。

入力とクイック選択は同じ条件を作るので、組み合わせて使えます。

AniMatch はまず **「理解した内容」** を、編集できる語を含んだ文で表示します。例：「**30分**で**軽く**見られる、**笑える**作品。」
- ✎ の語はタップして変更できます。
- × の語は外せます。
- ＋ で条件を追加できます。

続けて3作品を表示します。1位は大きなカード、2位・3位はその横に並びます。各カードはカバー画像の色で色付けされ、「笑い度：高」「1話が30分以内」「重い展開：ほぼなし」のような理由がつきます。

### 基本方針
**LLM は言葉を理解するだけ。何をおすすめするかは決めない。**

- LLM の役割は、自由文を検証済みの小さな `Context` オブジェクトに変換することだけです。
- `Context` からフィルタと目標ベクトルを作り、作品を順位づけし、理由を組み立てるのは決定的なコードです。理由はコード自身の数値から作ります。
- LLM が失敗した場合（タイムアウト、レート制限、不正な出力）は、ルールベースの日本語・英語パーサーが同じ形の `Context` を返します。**LLM が原因でアプリが止まることはありません。**

そのため、すべての結果を説明できます。デモの対象はエンジニア以外の方なので、この点を重視しています。

## 🚀 動作の仕組み (How It Works)

```
テキスト
 → [1] 解析：Gemini → JSON → Zod 検証            （失敗時はルールベースのパーサーが同じ形で返す）
 → [2] クエリ：Context → 目標ベクトル + フィルタ  （固定のマッピング、LLM なし）
 → [3] 順位づけ：安全フィルタ → ソフト条件 → スコア → 多様性 → 上位3件
 → [4] 説明：スコアの根拠となった事実から最大3つの理由（言語に依存しないキーで返す）
 → UI：「理解した内容」の文（語を編集すると LLM を呼ばずに再計算）+ 結果カード3枚
       言語ごとの辞書から日本語または英語で表示
```

**ベクトル。** 各作品は8次元のベクトルで表します：`laugh, cry, thrill, relax, think, romance, dark, heavy`
- 作品ごとの手作業の採点はしていません。AniList のジャンルとコミュニティタグ（タグの rank で重みづけ）から、短くレビューしやすい1つの対応表（[`tagMapping.ts`](src/data/tagMapping.ts)）を通して計算します。
- 各次元はデータセットの99パーセンタイルで正規化します。

**テーマ。** 気分は「どう感じたいか」、テーマは「何についての作品か」です。
- 料理・スポーツ・宇宙・吸血鬼・異世界など115のテーマを、実際の AniList タグから選んで [`themes.ts`](src/data/themes.ts) にまとめています。
- 作品がテーマに合う度合いは、該当するタグの rank の最大値です。

**スコア。** 重みは、ユーザーが実際に求めたものによって変わります。

| 求めたもの | スコア |
|---|---|
| 気分（または参照作品） | 0.5 × cosine + 0.3 × intensity + 0.2 × 評価 |
| 気分 + テーマ | 0.35 × cosine + 0.2 × intensity + 0.3 × テーマ + 0.15 × 評価 |
| テーマのみ（「cooking」） | 0.7 × テーマ + 0.3 × 評価 |
| 特になし（「なんでもいい」） | 0.6 × 評価 + 0.4 × 人気。「人気・高評価の作品」と表示 |

そのうえで補正を加えます。各項目の意味：
- **cosine**（7つの気分次元）：作品の「組み合わせ」が合っているか。
- **intensity**：最も重要な2つの気分を「どれだけ強く」持っているか。この項がないと、弱いけれど方向だけ合う作品が上位に来てしまいました。
- **評価**：AniList の averageScore / 100。
- **補正**：
  - 気力：疲れているときは重い作品を減点、一気見なら小さく加点。
  - 続編：シーズン3ではなく、見始める作品をおすすめするための減点。
  - 長編：長すぎる作品の減点。
  - 短編：時間が限られているときの加点。

**フィルタ。**
- **ゆるめないもの：** Ecchi はデフォルトで除外します。家族向けフィルタ、ユーザーが「避けたい」と言ったもの、明示された「映画 / シリーズ」と「完結済みのみ」も同様です。
- **絞り込みではなく小さな加点：** 最近の作品 / 昔の名作、有名作 / 隠れた名作。
- **結果が3件未満のときだけゆるめるもの：** 主な気分の下限、時間制限、テーマの下限の順。その場合、UI に「条件を少しゆるめました」と表示します。

**わからないことは、わからないと伝える。**
- 意味のない入力や、アニメ選びと関係ない依頼（天気、プログラミング、「指示を無視して…」）には、短いメッセージだけを返します。結果は表示せず、デフォルトの気分でごまかすこともしません。
- 作品名だけの入力（「鬼滅の刃」）は、その作品を「検索した作品」として先頭に表示し、続けて似た作品を並べます。
- アニメ以外の参照（「ハリー・ポッターみたいな」）は、気分とテーマに置き換えます。
- 「理解した内容」は入力した文から始まり（「cooking」→ 料理・グルメの作品。）、読み取れなかった部分があればそれも表示します。

## 💡 設計上の主な判断

### 1. LLM はパーサーとして使い、必ずフォールバックする
- **理由：** 作品を選ぶ LLM は選んだ理由を説明できず、事実と違うことを言う可能性もあります。本システムでは、LLM は Zod で検証されるスキーマを埋めるだけです。ルールベースのパーサーも同じスキーマに従うため、どちらの経路でも同じ形の結果になります。
- **デモ用の切り替え：** `/?parser=rules` を開くと、AI を使わない状態でも動くことを見せられます。画面のバッジに「AI解析」か「ルール解析」と解析時間が表示されます。
- **速度：** LLM は temperature 0、思考レベルは最低で呼び出します。ページ表示時にウォームアップ呼び出しを行い、最初のリクエストが遅くならないようにしています。

### 2. 作品ごとの手作業の採点はしない
人の判断は2つの短いファイルにまとめてあり、「次元ごとの上位10作品」レポート（`npm run report:vectors`）でレビューしました：
- [`tagMapping.ts`](src/data/tagMapping.ts)：タグ → 次元の対応。
- [`avoidMap.ts`](src/data/avoidMap.ts)：「避けたい」の語彙と家族向けフィルタ。

ここで決めた内容の例：
- ハーレム・お色気系のタグは「笑い」や「恋愛」に加算しません。
- 非常に多いタグ（例：`Tragedy` は約37%の作品に付いている）は重みを控えめにしています。

### 3. 推測ではなく計測で判断する
スコアの変更は毎回、6文の固定ベンチマーク（`npm run showcase`）で確認しました。結果はコミットハッシュつきで [`docs/showcase-log.md`](docs/showcase-log.md) に記録しています。このログから、どの問題をどう見つけて直したかが追えます。例：
- 弱いけれど方向だけ合う作品が勝っていた → intensity 項を追加。
- 参照作品があると「全部が高い」作品が上位に来た → intensity を上位2次元に限定。

すべての判断とその理由は [`docs/DESIGN.md`](docs/DESIGN.md) にあります。

### 4. 構造的に説明できるようにする
- 理由はデータだけから作ります：作品のベクトル、話数と長さ、AniList の評価、満たした条件。
- 各カードには折りたたみ式の「スコア内訳」があり、スコアの内訳をそのまま確認できます。

### 5. ロジックを複製せずに2言語に対応する
- サーバーは表示用の文字列を返しません。理由・お知らせ・チップはキーと値（例：`{ key: "fitsTime", minutes: 30 }`）で返し、UI が `src/i18n/ja.ts` / `en.ts` で表示します。そのため言語の切り替えは一瞬で、再リクエストも不要です。
- 作品名も言語に合わせます：JA モードでは日本語タイトル、EN モードでは英語タイトル（なければローマ字）。
- ルールベースのフォールバックも英語を理解します。否定（"no horror", "nothing too heavy"）や "something like X" にも対応しています。

## 📊 パーサーの評価

`npm run eval:context` は、日本語24件・英語8件のテスト文を両方のパーサーで解析し、言語ごとに結果を出します。否定、参照作品、あいまいな気分、「寝る前に少しだけ」や "an hour and a half" のような時間表現、映画/シリーズ・完結済み・年代・有名度の条件など、難しいケースも含めています。

| 項目 | 日本語・LLM | 日本語・ルール | 英語・LLM | 英語・ルール |
|---|---|---|---|---|
| 主な気分 | 100% | 96% | 88% | 100% |
| 気力 | 92% | 96% | 100% | 88% |
| 時間 | 100% | 96% | 100% | 100% |
| だれと | 100% | 100% | 88% | 100% |
| 完結済み | 96% | 100% | 100% | 100% |
| 避けたい / 参照作品 / 映画・シリーズ / 年代 / 有名度 | 100% | 100% | 100% | 100% |
| **全項目正解** | **21/24** | **22/24** | **6/8** | **7/8** |
| レイテンシ（中央値） | 約1.4秒 | 2ms 未満 | 約1.3秒 | 2ms 未満 |

英語の LLM 呼び出しの1件は18秒かかりました。アプリでは4秒のタイムアウト後にルールに切り替わります。

2つのパーサーは「別の文」で間違えます：
- LLM はあいまいな表現に強い（少しだけ → 30分、元気が出る → 笑い）。
- ルールは一瞬で終わり、失敗しません。
- LLM は言われていないことを付け加えることがあります（例：「ひとりで」や、参照作品から推測した気分）。

*注意：テスト文・プロンプト・ルールはすべて私が書いたため、この数値は楽観的です。英語は8件しかありません。他の人が書いた文で評価するほうが公平です。*

## 🛠️ 技術スタックとアーキテクチャ

* **言語：** TypeScript（strict）。データの定義は Zod に一本化しています。
* **アプリ：** Next.js（App Router）+ Tailwind CSS。順位づけはサーバー側の Route Handler で実行します。
  * フォント：ロゴと見出しは Dela Gothic One、それ以外は Zen Kaku Gothic New（`next/font`）。
  * レイアウトは [`docs/ui-mockup.html`](docs/ui-mockup.html) に準拠しています。
* **LLM：** `@google/genai` 経由の Gemini。1つの小さなインターフェース（[`llm.ts`](src/lib/context/llm.ts)）の裏に隠してあり、1ファイルの変更だけで他のモデルに差し替えられます。
* **データ：** AniList GraphQL API から人気上位1000作品を一度だけ取得し、[`anime.json`](src/data/anime.json) に保存しています。データベースは使いません。
* **テスト：** `tsx` 経由の `node:test`。

### プロジェクト構成
```bash
src/
├── app/                 # UI（ページ + コンポーネント）と API：/api/recommend, /api/warmup, /api/feedback
├── i18n/                # ja.ts / en.ts の辞書、表示用の関数、LangProvider（JA/EN 切り替え）
├── data/                # anime.json（AniList）、tagMapping.ts、avoidMap.ts、themes.ts ← 人の判断はここだけ
└── lib/
    ├── context/         # schema.ts（Zod）、llm.ts、rules.ts、parse.ts（LLM → フォールバック）、chips.ts、quickPicks.ts、merge.ts
    ├── engine/          # query.ts、rank.ts、explain.ts、filters.ts
    ├── messages.ts      # 言語に依存しない Reason / Notice / チップのラベルの型
    ├── vectorize.ts     # タグ → ベクトル
    ├── dataset.ts       # 読み込み + ベクトル + シリーズのグループ化
    └── recommend.ts     # パイプライン全体
scripts/                 # fetch-anilist、report-vectors、showcase、eval-context、try
eval/                    # context-cases.json（パーサーのテスト文）
docs/                    # DESIGN.md（すべての判断）、showcase-log.md（変更前後の記録）
```

## 🏃‍♂️ 実行方法 (How to Run)

1. **依存関係のインストール：**
   ```bash
   npm install
   ```
2. **LLM の設定（任意）。** キーがない場合は、すべてのリクエストがルールベースのパーサーで処理されます。`.env.local` を作成してください：
   ```bash
   GEMINI_API_KEY=your-key
   GEMINI_MODEL=gemini-flash-lite-latest
   # LLM_TIMEOUT_MS=4000   # 任意、デフォルト 4000
   ```
3. **カバー画像のダウンロード（デモでは推奨）：**
   ```bash
   npm run fetch:covers   # 約10秒、public/covers/ に 17MB の webp（git 管理外）。何度実行しても安全
   ```
   UI はローカルのファイル → AniList の CDN → プレースホルダーの順に使うので、デモが CDN に左右されません。
4. **アプリの起動：**
   ```bash
   npm run dev
   ```
   [http://localhost:3000](http://localhost:3000) を開きます。
   - [`/?lang=en`](http://localhost:3000/?lang=en) または `/?lang=ja` で言語を指定して開けます。指定がなければ、最後に切り替えた言語を覚えています。
   - [`/?parser=rules`](http://localhost:3000/?parser=rules) でルールのみのモードになります。
   - 組み合わせも可能です：`/?lang=en&parser=rules`。

### その他のコマンド
```bash
npm test                 # ユニットテスト（エンジン、日英ルールパーサー、フォールバック、チップ、i18n）
npm run showcase         # 日本語8文 + 英語6文 → 表を出力し、docs/showcase-log.md に追記
npm run eval:context     # LLM とルールの精度・レイテンシ（Gemini を呼び出し、約2分、無料枠に合わせて間隔を空ける）
npm run try -- "文"      # 1文をパイプラインに通す（--llm で Gemini を使用）
npm run report:vectors   # tagMapping.ts / avoidMap.ts のレビュー用レポート
npm run fetch:anilist -- --keep-ids   # 同じ1000作品を AniList から再取得（通常は不要）
npm run build && npm run lint
```

結果カードの 👍/👎 は `logs/feedback.jsonl` に追記されます（ローカルのみ。学習にはまだ使っていません）。

## ⚠️ 制限事項 (Limitations)
1. **対応表は手で調整している。** タグ → 次元の重みは私の判断です。実データでレビューはしていますが、学習したものではありません。将来はフィードバックのログを使って調整できます。
2. **評価セットが小さい。** 作者が書いた32文（日本語24・英語8）です（上の注意を参照）。
3. **データセットの規模。** 人気上位1000作品を O(N) で全件走査しています。この規模なら問題ありませんが、さらに大きなカタログにはベクトルインデックスが必要です。
4. **カバー画像** はダウンロード済みならローカルのファイル、なければ AniList の CDN、それも失敗したらプレースホルダーを表示します。画像の権利は権利者にあるため、リポジトリには含めていません。
5. **「完結済みのみ」** は、このデータセットではほとんど絞り込みません。人気上位1000作品のうち997作品が放送終了しているためです。

作品データとカバー画像：[AniList](https://anilist.co)
